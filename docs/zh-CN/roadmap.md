# 实施路线与任务依赖

[English](../en/roadmap.md)

## 计划基线
按一名主要开发者持续投入，预计 6–8 周形成公开 beta；是工作量估计，不是发布日期承诺。所有阶段当前为 planned，文档交付不代表完成实现。

| 阶段 | 工作量估计 | 交付物 | 退出条件 |
| --- | --- | --- | --- |
| P0 设计验证 | 3–4 工作日 | 3 份 RFC、版本矩阵草案、20 任务 | 双模式、数据语义、协议入口和预算决策可执行 |
| P1 核心闭环 | 7–10 工作日 | Schema/core/runtime，四类 intent、原生模式、SVG | 无密钥演示可运行，契约和浏览器测试通过 |
| P2 Agent 资源 | 5–7 工作日 | CLI/MCP、诊断、recipes、检索与样例 | Agent 工具闭环和真实 MCP 客户端验证 |
| P3 协议接入 | 7–10 工作日 | OpenUI/A2UI、React、状态与交互 | 两宿主展示/更新/事件证据；profile 分开声明 |
| P4 beta 质量 | 5–7 工作日 | 100 任务目标、兼容报告、双语站点、发布演练 | 实际 tarball 验证、已知限制和所有发布门禁 |

顺序依赖：P0 → P1 → P2；P3 的上游调查在 P0 开始，适配实现依赖 P1；P4 汇总各阶段证据。不要等 P3 才发现 A2UI 的版本/宿主机制不适用。

## 第一个纵向任务
销售数据 → 折线 → 地区分组 → 堆叠柱状 → 替换数据 → 点击地区返回稳定选择。用原生与 intent 两入口，先 DOM 再 MCP/协议宿主。允许在 alpha 先交付一个协议，beta 才宣称两个均验证。

## P0 具体任务
- S001：核实本地与远端历史、安全同步文档，创建初始化 Spec。
- S002：锁定工具链、上游协议/SDK、ECharts 基线和 npm scope。
- S003：RFC-0001 双输入与数据语义；RFC-0002 操作/状态/事件；RFC-0003 适配器/能力/版本策略。
- S004：选择 20 个代表任务与失败例，确定资源预算和评测记录格式。
- S005：建立最小工程骨架与文档检查，验证一个 bar 纵向样例；随后进入 P1。

这些 ID 是计划条目，不是已经存在的 GitHub Issue。每项开始时创建正式 Spec/任务并链接证据。

## 发布范围
alpha 必须有原生入口、四种 intent、数据引用、校验编译、DOM/SVG、CLI/MCP、一个协议、资源和明确限制。beta 增加第二协议、冲突/幂等验证、状态保留和发布级证据。
延期必须明确减少发布声明或调整里程碑，不能将未验证能力写进 supported 列。重大范围变化由维护者更新本路线及对应 Spec。

## 风险与应对
| 风险 | 应对 |
| --- | --- |
| 原生 option 面过大 | 能力 profile、明确验证层级、受控扩展 |
| 协议持续变化 | 精确版本锁定、契约测试、独立适配包 |
| 简化规范变成另一套庞大语言 | 四图表起步、用任务证明新增字段价值 |
| 模型生成不稳定 | 结构化诊断、有限修复、公开对照评测 |
| 双语与 Schema 漂移 | 共同来源生成、配对检查、同 PR 更新 |
| 范围过大 | 每阶段纵向交付，推迟框架与托管服务扩张 |

## COSUI 范围补充（2026-10-30）
COSUI 纳入 P3 必需目标，JSON/San 与 Marklang 分别验收。见[调研与验收计划](cosui-integration.md)。建议顺序：首个 OpenUI 闭环、COSUI JSON、COSUI Marklang，再在标准 A2UI 版本明确后接入。原 P3 工期仅覆盖两个协议，需要重估。alpha 可保留一个已验证协议；即使排在 beta 后，COSUI 仍是必须完成且分别提供证据的工作。目前已实现 COSUI JSON/San、Marklang 与 A2UI v0.9 React 的实验性图表 profile，验证边界见[集成指南](genui-integrations.md)。

## 当前进度（2026-10-31）
核心、本地 CLI/MCP 和实验性协议 profile 已实现并有本地证据。模型资源第一阶段提供[双语模型入口](model-entry.md)、生成的资源目录和 [20 项公开合成开发任务](evaluation-baseline.md)。真实模型评测、独立隐藏数据、真实流式传输、交互状态保持、包安装和发布仍属后续工作。上方 P0–P4 工期与 planned 状态为历史规划，并非当前完成情况。

## 本地模型检查点（2026-10-31）
已使用官方 MCP stdio 客户端对两个本地 Ollama 模型开展小样本试验。逐任务证据与限制见[本地试运行](local-model-pilot.md)；完整任务、重复运行、独立隐藏数据及桌面 MCP 验证仍待完成。

## 顺序更新检查点（2026-10-31）
可选 runtime 控制器及 A2UI 顺序更新宿主 profile 已有本地浏览器证据。流式传输、交互状态保持及 COSUI Marklang 顺序接入仍待实现。

## 多协议顺序更新（2026-10-31）
OpenUI 和 COSUI JSON 的可选宿主 profile 已接入会话控制器并有本地浏览器测试；版本和传输由宿主负责。

## 核心审查检查点（2026-10-31）
[能力审查](core-capability-review.md)记录 28 个代表任务及证据层级；[0.2 协议草案](core-protocol-0.2.md)已部分实现为实验性 intent 子集。应先明确原生校验边界和数据语义，再扩展图表类型和主题。

## 图表能力检查点（2026-10-31）
实验性 0.2 已增加显式共享/右轴的柱线组合图与漏斗图子集；模型评测、热力/雷达、主题无障碍、状态保持和分发验证仍未完成。
