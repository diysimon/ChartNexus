# RFC：基础质量、宿主展示与四类图表扩展

[English](../en/technical-design-2026-10-31.md)

## 状态与设计原则

这是[技术审视](project-review-2026-10-31.md)后**部分已实现**的 RFC。M0–M3 已通过本地验收；实际 API、证据和限制见 [0.3 契约](contracts-03.md)及[聊天宿主质量](chat-host-quality.md)。D07/D08 渲染器与宿主地图资产已实现，[M3 指南](chart-expansion-03.md)冻结实际接口和限制；D09/D10 工具与分发已在 [M4](trial-distribution.md) 实现；已推送实现通过Linux CI，完整模型评测及最终报告验收仍待完成。执行顺序见[行动计划](action-plan-2026-10-31.md)。

目标是基础、通用、可解释的聊天图表：少量有用配置、可信数据语义、两套简洁主题、五档展现、多个模型与宿主共用一个核心。维持不联网、不执行模型代码、不隐式排序/聚合/转换、不臆造数据。树图指 **tree 节点连线树**，不包含 treemap；地图指 **GeoJSON 区域着色图**，不包含瓦片、在线底图、轨迹、3D 或地理编码。以上高级方向不作为此次交付条件。

## D01：先修复现有语义，保持兼容

- 全零饼/环形图：保留输入与数据身份，显式设置 `stillShowZeroSum:false`，返回 `NO_SHARE_DATA` 提示和可访问的“无可计算占比”文本；不得显示等分占比。空数据与全零状态分开，不能把 null 改成 0。原生 guarded 模式保持其明确的扩展边界，不悄悄重写所有原生图。
- 分组：内部系列 key 由字段及原始分组值编码得到，不以显示名称作为唯一身份。空值标签和重名标签通过确定性消歧显示，并在元数据中保留原值；同一系列在重排后 key 不变。禁用歧义图例操作前必须有诊断或映射，不能静默合并系列。
- 原生校验继续区分 guarded-partial 与 strict-basic。工具结果必须返回使用的校验级别；“结构合法”“编译通过”“可渲染”“宿主验证”不合并为一个 supported 布尔值。
- 0.1/0.2 仅做有明确依据的修复。会改变合法输入结构、默认展示或事件身份的变更放入新版本或显式宿主开关。修复改变错误输出仍应写迁移说明和回归例。

## D02：0.3 判别联合与模型入口

建议将结构扩展集中到实验性 **ChartDocument 0.3**。0.1 原生及 intent、0.2 intent 保持可读，暂不实现 0.3 原生。这样避免强迫 tree/Sankey/radar 提供没有意义的 x/y，也避免在 0.2 的一个 chart 对象上继续累加全局可选字段。

`chart.type` 判别十一种独立分支，分支只包含该类型允许的字段。已有七类的有效语义不变；引用共同的字段、单位、排序定义。JSON Schema 负责分支结构与局部类型；编译器负责跨字段引用、数据范围、环、重名、资源预算等语义约束。Schema 合法不保证数据语义合法，但 heatmap 缺少颜色字段这种局部结构错误应由 Schema 拒绝。

每个模型入口同时提供：目标版本、选定图表的精简 Schema、对应能力、一个成功和一个失败/修复示例。不要给所有模型强制塞完整联合；提供完整 Schema 与投影 Schema 两种资源。投影以同一源生成并执行契约测试，不手写第三套约束。保留现有 `get_chart_schema` 默认行为，新增显式 `chartType`/目标版本选择；不静默把旧默认升级。

展示建议简化为可选 `presentation: {theme: "light"|"dark", detailLevel: ...}`，仅在新版本移除模型无需操心的 theme.version；宿主仍决定实际主题和背景。老版本 `{id,version}` 通过显式迁移转换。只允许可证明保持语义的迁移，聚合后的身份等不能猜测。新版本对未知字段报精确路径，不以静默删除字段“修复”。

## D03：编译、展示与渲染分层

保留现有包边界，优先在 core 内按职责拆文件，而非立即增加一串新包：

```mermaid
flowchart LR
  A[文档与可信数据] --> B[Schema 与语义校验]
  B --> C[数据解析与显式变换]
  C --> D[按图表类型编译]
  D --> E[RenderPlan 与语义元数据]
  E --> F[纯展示规划]
  G[宿主尺寸/主题/策略] --> F
  F --> H[浏览器 runtime 或 SVG]
  H --> I[带版本与身份的宿主事件]
```

建议内部职责：`data/resolve`、`data/transforms`、`charts/{type}`、`presentation/{theme,detail,layout}`、`diagnostics`。先以现有 golden 数值/身份测试保证重构等价，再增加类型。不要用“先编译为另一个图，再替换 type”承载新图表语义。

保留现有 RenderPlan.option 用于 ECharts，增加版本化元数据（编译器 build、展示版本及能力摘要），不建立完整的第二套图形语言：系列/项 key、原始显示标签、单位、缺失值、无数据状态、必要图例/色阶和表格列定义。错误仍走 Result；非致命调整使用结构化 notices（code/path/params），与错误分开。旧 `adjustments` 通过兼容映射保留。

纯展示函数概念签名：`resolvePresentation(plan, context) -> {option, notices, accessibility}`。context 包含明确的宽高、light/dark、transparent/theme、五档和有限测量结果。core 不读取 DOM、系统主题或字体；浏览器负责测量，SVG 入口提供固定尺寸/字体假设。没有尺寸时使用明确的静态默认，不声称完成响应式布局。

## D04：尺寸、主题、五档和非图形替代

**优先级**：安全/资源限制与语义最低信息 → 宿主可访问性和展示策略 → 文档明确偏好 → 档位默认。所有可见调整给出 notice。宿主可以拒绝超过布局容量的展示，但不得偷偷删数据、换单位、变图表类型或挑选 Top N。

初始设计基准为图表内容宽度（非窗口宽度）：小于 240px 时推荐文本/数据表回退；240–359px 紧凑；360–559px 常规；560px 及以上宽版。这是待验证的设计参数，不是新的数据拒绝条件。高度、轴数量、标签测量也参与布局；双轴在窄容器可能需要更高尺寸或回退，不强行塞进同一模板。

| 档位 | 默认可见元素 | 不允许省略的信息 |
| --- | --- | --- |
| minimal | 图形、必要定位信息，标题可由聊天文本承载 | 数据身份、单位、色阶和非图形替代 |
| simple | 增加已提供标题及主要刻度 | 同上 |
| standard | 常规刻度、轻网格、必要图例；默认档 | 同上 |
| detailed | 在空间允许时增加数据标签与补充说明 | 不因为标签密集丢数据 |
| comprehensive | 更完整的刻度/单位说明及支持的探索操作 | 不自动开启双轴、缩放或复杂工具栏 |

五档是信息密度策略，不是五套不同图表能力；无坐标图可能相邻档位相同，文档明确说明。显式请求大量标签仍受可读性策略约束，可提示隐藏/改放表格，不能像当前默认那样无条件允许重叠。

标题和轴名最多预留两行，超出后提供完整文本入口；分类刻度依据测量预算截断/抽稀，原始值保留。布局顺序为标题 → 图例 → 轴及色阶 → 绘图区 → 数据标签，不互相覆盖。浏览器长图例使用可键盘操作的宿主控件或可访问分页；静态导出不能依赖滚动，需完整布局、增大输出尺寸或返回明确的导出限制提示。

两主题由统一 tokens 提供文字、次级文字、轴、网格、tooltip、分类色和连续色。透明背景只能在宿主声明主题/背景条件下保证可读性；不从模型文本猜背景。设置 `prefers-reduced-motion` 的外层支持，当前默认无动画保持。常规文字在规定浅/深表面的对比目标 ≥4.5:1，必要图形/控件目标 ≥3:1；颜色不足以单独编码身份。仅对实际检查组合声明符合，不宣称通用 WCAG 认证。

每张图提供确定性摘要和数据表（含单位、null、原始类别、数据来源标识），不生成因果分析或事实补全。表格按需要分页、带计数，不能把 UI 分页当作数据删减。图例切换、数据查看应有键盘入口；hover tooltip 只作为补充。SVG 与摘要/表格的关联交付，不把静态 SVG 描述为交互界面。

## D05：生命周期、身份、状态与事务

适配器采用 `unmounted → waiting-for-size → ready → disposed` 状态机；等待期间保留最新完整有效输入，零尺寸不是持续报错循环。卸载清理观察器和待处理工作。保留旧 mountChart 的立即失败语义，通过外层挂载协调器支持等待，避免破坏既有调用方。

数据更新与布局更新分开：resize/theme 不增加数据 revision；成功提交新文档才增加 revision。布局更新使用最近一次成功计划，不重新解释可能已被调用方修改的输入。失败不修改已提交计划、revision 或身份映射。`clear`、恢复、resize 和回调异常明确转为可观测状态，回调错误不伪装成数据错误。

新增可选的稳定行 key 字段（新版本中声明，非空唯一字符串）；事件优先使用该 key，旧输入继续返回 position 并明确其只对当前 revision 有效。聚合事件继续返回 aggregate 身份，不臆造原始行 ID。树节点、桑基节点/边、地图区域有各自类型化身份，不能硬塞入一个 rowIndex。

交互状态首先支持图例，使用语义系列 key/项 key 保存；更新后取新旧有效 key 交集，新项默认可见。图表类别、字段映射或单位改变时重置不兼容状态并报告原因。缩放仅对明确支持的连续轴启用，保存值域而非像素；裁剪到新范围，空交集重置。现有不支持 dataZoom 的 profile 不因此被宣称已经支持。

Marklang 使用可测量但对用户不可交互的 staging 容器，不能用 display:none 导致零尺寸；预校验、资源准备和所有图表挂载完成后原子替换。失败只销毁 staging。多图文档总预算与最多 16 图共同检查；保留旧图时计入暂存内存预算。

## D06：真实流式与协议一致性

把通用 JSON 文档缓冲器从 A2UI 专属导出中逐步抽到协议无关模块，保留旧 re-export。传输层负责 UTF-8 增量解码、Ollama NDJSON/SSE 等 framing、超时和 AbortSignal；缓冲器只接受已解码内容，不伪装成协议解析器。

一次生成绑定 operationId、开始时的 baseRevision 和 requestEpoch。结束时必须同时满足：传输成功终止标记、无取消、单个完整 JSON、结构/语义合法、版本仍可提交。收到一个可解析 JSON 后连接截断不算成功。取消后迟到片段丢弃，错误显示在旧图旁边；旧图不清空。一次失败修复最多再请求模型两次，每次完整校验并标明初次/修复结果，不能无限循环。

OpenUI Lang、A2UI v0.9、COSUI JSON、Marklang 各自列出：SDK 版本、文档表示、完整性信号、更新/卸载、事件、错误、主题、尺寸和资源注册。提供相同的适配器合约测试，但使用真实上游 SDK 的独立宿主；不把 ChartNexus operation 描述为上游标准字段。先本机 Ollama 实流，再在明确授权及配置的环境验证其他模型；远程 MCP 服务不是这一轮必须新增的基础设施。

## D07：四类图表的受限契约

以下字段为 0.3 设计草案；每类图必须独立完成 Schema、编译、Browser/SVG、事件、主题、表格、示例、诊断和 Agent 评测后才标 supported。既有七类不回退为未实现。

| 类型 | 建议数据与字段 | 必须验证 | 初期边界 |
| --- | --- | --- | --- |
| radar | 常规表，每行一个对象；`encoding.item.field`；`indicators:[{field,label,min,max,unit?}]` | 3–8 个不同数值指标；显式有限范围 min<max；每行值在范围内；对象身份唯一 | 1–6 个对象；不推断范围、不归一化；缺失指标先明确拒绝 |
| tree | 常规表；`encoding:{id,parentId,label}` 引用字段；root 的 parentId 为 null | 唯一非空 ID、父节点存在、单根、无环、所有节点可达 | 节点连线树；≤1000 节点、深度≤16；默认展开≤2 层；节点计数不等于数值求和；暂不含 treemap |
| sankey | `data.kind:"graph"`，nodes/links 各自为 inline/reference 表；`encoding:{nodeId,nodeLabel,source,target,value}` | 节点/边身份、端点存在、非负有限流量、禁止自环/有向环；重复 source-target 明确拒绝，不自动合并 | ≤200 节点、≤1000 边；零权边不绘制但表格保留；不推断守恒，流入/流出及差值可在元数据说明 |
| map | 常规区域表；`encoding:{region,value}`；`mapRef:{id,revision}`；显式 colorDomain | region 精确对应可信地图区域 key；重复/未知区域报错；数值在范围内；null 与缺失区使用缺失色 | 仅区域着色；模型不能提供 GeoJSON/URL；不内置政治边界选择；使用宿主资源与授权说明 |

树图节点名称可以重复，身份不能重复；显示层不修改树拓扑。折叠只影响可见展开状态，不删除数据；SVG 若无法表达全部要求内容应明确标记折叠概览或选择完整导出。桑基流量不是占比，不能自动改为百分比。雷达不同单位按明确范围展示，必须提供指标范围说明，避免误导比较。

所有新图仍受整体 1 MiB 文档/数据预算；图级限制是附加上限，并非允许超过整体预算。树使用 O(n) 图遍历，桑基使用 O(V+E) 环检查；避免直接递归模型的任意深度对象。限制在 schema、capabilities 和运行时一致发布。


### 可审阅的字段示例（草案，不可直接交给当前运行时）

以下仅为 `chart` 分支片段，公共 `schemaVersion:"0.3"`、id、data 和 mode 外壳沿用前述定义。所有编码引用使用 `{field}` 对象，避免同一协议混用字符串与对象。

```json
{
  "type": "radar",
  "encoding": { "item": { "field": "team" } },
  "indicators": [
    { "field": "speed", "label": "速度", "min": 0, "max": 100 },
    { "field": "quality", "label": "质量", "min": 0, "max": 100 },
    { "field": "coverage", "label": "覆盖", "min": 0, "max": 100 }
  ]
}
```

```json
{
  "type": "tree",
  "encoding": {
    "id": { "field": "nodeId" },
    "parentId": { "field": "parentId" },
    "label": { "field": "name" }
  }
}
```

```json
{
  "type": "sankey",
  "encoding": {
    "nodeId": { "field": "id" },
    "nodeLabel": { "field": "label" },
    "source": { "field": "from" },
    "target": { "field": "to" },
    "value": { "field": "amount" }
  }
}
```

Sankey 的 nodeId/nodeLabel 在 `data.nodes` 表中解析，其余在 `data.links` 中解析；`data` 为 `{kind:"graph",nodes:<TableSource>,links:<TableSource>}`。禁止重复 source-target 后，边身份可由有序端点对确定，不能用数组下标；节点显示标签可以重复，ECharts 映射须经实际 SDK 验证。两表一次解析为同一提交快照，registry 中 revision 不匹配则整次失败。

```json
{
  "type": "map",
  "mapRef": { "id": "sample-regions", "revision": "1" },
  "encoding": { "region": { "field": "regionId" }, "value": { "field": "amount" } },
  "colorDomain": { "min": 0, "max": 100 }
}
```

这些示例仅用于 RFC 审阅，不加入当前成功 recipes 或 supported 能力表。实现 Spec 必须补齐完整文档、有效数据与失败样例。

## D08：地图资源与信任边界

新增宿主 MapRegistry，与 DataRegistry 分离。每个资源有稳定 id、revision、内容摘要、区域 key 集、投影/坐标约定、许可证和来源；地图几何不放入模型提示或 ChartDocument。第一版仅接受经宿主检查的 GeoJSON FeatureCollection、Polygon/MultiPolygon，排除 SVG 地图及外链。第一版只声明 WGS84 经纬度，拒绝其他 CRS 和隐式投影转换；检查有限坐标、经纬度范围、闭合环及最小环长度。建议独立资源预算：每地图≤5 MiB、≤20000 坐标点、≤1000 区域，每进程最多 8 个已注册版本且源几何合计≤20 MiB；仍需性能实测确认后冻结。

core 只读取安全的地图元数据和区域 key；渲染层对内容摘要及限制复核后注册到 ECharts。注册名由 id/revision/hash 命名空间化，避免多宿主同名资源冲突。ECharts 全局注册表没有可靠卸载语义时采用有上限的注册策略；版本不匹配或容量满明确失败，不覆盖已被其他图引用的资源。

SVG worker 必须获得相同的可信资源快照并在 worker 内注册，受输出/时间预算限制；无资源、版本不匹配或几何非法时返回稳定诊断，不能只让浏览器可用。测试用自制两个多边形，不下载真实行政区边界；发布前独立核查任何拟附带资源的分发权。

## D09：Agent 资源、诊断与评测

建立显式注册表记录图表、版本、阶段、运行方式、约束、示例、修复例、上游版本、来源与许可。生成能力表、模型 Schema 投影、工具说明、recipes manifest、RAG 条目、MCP 发现和支持矩阵；禁止通过资源 ID 的字符串后缀猜能力版本。实验/已验证/未运行逐维度记录，不能拿“编译支持”推导“所有宿主支持”。

诊断保留稳定 code、JSON Pointer、语义原因和可执行但不执行的修复建议；unknown-field 列出有界合法字段，Schema 类型/枚举错误给出期望。业务数据不得自动改写来通过校验。宿主策略通过服务配置注入，模型的工具参数只能提出偏好，不能覆盖信任/资源/主题策略；现有 MCP 参数兼容迁移需明确说明。

评测分三个集合：公开教学 recipes；公开开发回归；不进入 MCP/RAG/训练包的隐藏任务。每项隐藏任务的来源、任务族、数据、预期及 hash 在评测侧管理，模型只看到任务和必要数据。冻结模型、prompt、Schema/编译器 hash、温度/seed、预算，再执行；修改提示后旧失败例归为开发复测，不能仍叫隐藏测试。训练资源可发布合法来源的公开示例，不把“训练友好”等同于本项目必须训练模型。

指标分开：JSON/结构有效、编译成功、数据/单位/身份保真、任务语义正确、初次成功、修复后成功、调用轮数、工具错误、取消与延迟。真实模型是否选图正确与确定性渲染是否正确分别评分。先用现有本地模型建立基线；模型无关架构不等于每个模型均已验证。样本量、单次/重复、置信区间和失败例必须公开说明，不将小样本结果宣称普遍成功率。

## D10：分发、性能与发布门禁

全包 tarball 在干净临时工程安装，不能依赖仓库路径或 workspace 链接；明确 Node 22/24、ESM exports、JSON 资源、worker 相对路径、CLI bin、MCP stdio、React/San peers、LICENSE/NOTICE。先完整本地演练，不发布 npm。A2UI 与其他 adapter 的 peer/依赖版本单独校验，避免扩大未经验证的兼容范围。

浏览器端在 ECharts 模块清单明确后采用按需注册；SSR/worker 必须使用同一受控能力集合。先测量依赖组成再定体积门槛，不把演示 1.29 MB 当成 SDK 大小。记录典型 100/1000 行与边界负载的编译、首次渲染、更新、内存和 dispose 循环；同一机器以基线比例检查退化，绝对 SLA 等真实宿主测量后确定。

CI 分离生成/类型/语义、浏览器、包安装三个必需任务；失败保留结构化结果与必要截图。真实模型评测不放入每次 PR 的昂贵/不稳定默认门禁，可手动或按明确授权安排。文档检查增加状态/日期配对与 evidence 引用，不依赖“段落字数差不多”。新功能 rollback 以独立 profile/版本禁用，不删除用户数据或强迫旧文档迁移。

## 备选方案与不采用原因

- 直接开放全部 ECharts option：模型错误面和安全/兼容成本过大，继续保留受控原生入口即可。
- 继续扩充 0.2 单一 chart 对象：使无效组合增加，层级和图数据被迫伪装成 x/y；采用新版本判别联合。
- 新建大型通用可视化 IR：当前规模不足以证明必要，RenderPlan 加最小语义元数据即可。
- 自动猜主题、范围、排序、地图、比例或缺失值：易改变意义，交由明确契约/可信宿主。
- 一次提交全部图表及重构：无法定位回归；每类图纵向验收，统一登记最终状态。

## 仍需证据解决的点

具体字体测量策略、断点、地图资源上限、Node/浏览器性能预算及模型成功阈值需在固定环境验证；不是让用户再次选择常规实现细节。无关外部服务不可用时可继续本地工作，但不得将对应真实验证标为通过。M1/M2 已冻结基于保守文字预算和显式回退的有界布局，不承诺任意字体的精确测量。其余提案只有对应 Spec 记录通过证据后才算已实现。
