# 详细行动计划与验收门禁

[English](../en/action-plan-2026-10-31.md)

## 范围、状态和执行方式

依据[审视报告](project-review-2026-10-31.md)和 [RFC 技术设计](technical-design-2026-10-31.md)，覆盖原九项工作及雷达、节点连线树、桑基、地图。**M0–M3（A01–A15）已在本地完成，M4 仍待完成**；审视基线为 147 测试和 18 浏览器测试，M0 验证为 176 测试和 21 浏览器测试。M1/M2 通过 207 项单元/集成测试、33 项浏览器测试，并取得一次真实本地 Ollama 流式及取消冒烟证据。M3 通过 230 项单元/集成及 44 项浏览器测试，本轮未新增真实模型基准结果。[审视 Spec](../../specs/0030-project-review/spec.zh-CN.md)只验收审视文档本身，[0029](../../specs/0029-quality-expansion/spec.zh-CN.md)继续作为未完成范围总表。

每次只推进一个可审阅纵向任务：明确 Spec/AC → 实现及同步资源 → 定向测试 → 相关全量门禁 → 更新证据。常规选择由执行者按 RFC 决定，不反复让维护者确认；协议破坏性变更按 RFC/版本规则记录。保持本地可运行预览。不自动提交、推送、发布或创建外部 Issue；那些是独立动作。

下列 Axx 是本地计划 ID，不是 GitHub Issue。估计均为一名熟悉仓库的开发者的实际工作日，包含代码和验收，不包含等待外部环境；不是交付日期承诺。M0 完成后按事实重估。禁止为了按期宣布完成而删除验收条件。

## 验证矩阵与完成判据

**确定性语义**：每类覆盖最小有效、空/null/零、极值/超限、未知字段、错误编码、重排/更新、数值和身份不变；图数据额外覆盖拓扑。核心的已知错误反例必须成为正常回归测试，不能只存在审视脚本。Schema 投影、能力与生成资源一致性由自动检查承担。

**展示**：核心七类及新增四类分别验证两主题、五档；先以 option/元数据覆盖组合，再挑代表性的浏览器/SVG视觉例，避免声称每个组合都做了人工检查。内容宽度 240/320/480/768px，高度 240/320/480px，长中英文类别、长标题、多个系列、零/缺失值、双轴及热力色阶。每个参考截图固定浏览器、字体、数据、尺寸、主题与动画设置；几何检查加人工抽样，不以 scrollWidth 代替图形不重叠判断。小于最小宽度测试回退和完整数据访问。

**生命周期**：零尺寸、显示/隐藏、反复 mount/dispose、连续 resize、系列删除、图类切换、用户图例选择、非法文档、渲染故障注入、上游组件重建。故障测试检查旧图和 revision，而不仅是返回错误。

**模型**：建议先建设 30 个公开开发任务和 60 个隐藏任务；隐藏集由 33 个图表任务（11类×3）、12 个修改任务、9 个非法/不支持输入任务、6 个恢复任务构成。任务族和数据变化应超过换名称换数值，避免模板泄漏。对实际可用模型各执行 3 次记录重复性，模型型号/量化/参数分别报告；跨服务验证有实际配置才执行。33 项图表任务不意味着所有合理答案只允许一种图，评分优先不变量与任务约束。

候选使用门槛：确定性数值/身份不变量必须全部通过；安全和取消不误提交；无未处置 P1。真实模型建议目标为首次结构有效率≥95%、最多两次修复后任务正确率≥95%，但应在 M1 基线后冻结，并报告分母与置信区间。未达目标的模型标为实验/不推荐自动执行，不对数据做隐式“纠正”来冲指标，也不将模型差异归因于协议不兼容。不得声称这证明“所有大模型均可用”。

**分发/性能**：至少 schema/core/runtime/render/agent/cli/mcp 与三个 adapter 包；Node22/24；锁定浏览器与 React/San/SDK。浏览器运行和 Node 导入分别验证。记录构建原始/gzip 体积及实际加载组合；在同机对 100/1000 行和能力上限做基线。绝对耗时门槛在首次测量后写入配置，后续可用同机 p95 不退化超过20%作为候选指标，噪声需重复测量确认，不能随意放宽。
