# 安全与可靠性要求

[English](../en/security-reliability.md)

## 信任边界
模型输出、上游协议载荷、数据字段、标签和样例文本均视为不可信数据。JSON 合法不代表安全或语义正确。宿主注册代码属于另一个信任边界，不得由模型自助注册。
核心默认无网络、无文件系统、无执行权限。render/CLI/MCP 的文件与网络权限由宿主配置；模型不能指定任意输出路径、任意读取路径或远程请求目标。

## 必需控制
- JSON 解析后验证结构、深度、对象键、数组长度与字符串大小；拒绝危险原型键路径，更新合并不能产生原型污染。
- 模型路径禁用 eval/new Function、脚本 formatter 和任意事件代码。HTML tooltip/标签应使用安全文本或经过审计的转义策略。
- 图片、symbol URL、地图/扩展资源等外部资源默认禁用或要求宿主注册并允许；静态 SVG 需检查链接、可执行内容和外部引用，不能把它当天然安全 HTML。
- 对输入字节、行数、series 数、图像尺寸、耗时和产物大小设显式预算；具体值 P0 用基准确定，发布前不得仍无限制。
- 异常、日志与遥测默认不包含数据行、完整提示词或凭证。遥测默认关闭；启用时说明数据字段和目的。
- 服务端渲染并发、取消与超时需要测试，防止单个图表耗尽进程资源。

## 故障处理
使用稳定诊断区分用户输入、能力不支持、宿主数据失败与渲染故障。保留上一有效状态，清理失败实例与资源。重试有次数/时间预算；副作用操作使用幂等约束。
远程 MCP、多租户隔离和服务托管不属于首版；后续引入时必须新增鉴权、授权、配额、会话隔离与部署 Spec，不能直接公开本地 stdio 服务。

## 供应链与报告
新依赖检查许可、来源和运行脚本。发布使用最小权限、固定 Action SHA 和可追溯构建。
仓库私密漏洞报告渠道需维护者确认并启用；未确认时不声称可用或承诺响应 SLA。发现漏洞不在公开 Issue 贴密钥或可利用细节，先通过仓库维护者已公布的私密渠道联系。上线前完成渠道配置并更新根 SECURITY 文档。
