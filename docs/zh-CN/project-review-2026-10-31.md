# ChartNexus 技术审视：2026-10-31

[English](../en/project-review-2026-10-31.md)

## 结论与审视范围

当前项目是**具备真实本地闭环的实验性实现**，不是已经完成质量验收的通用 GenUI 图表层。核心方向正确：纯数据契约、与模型无关的编译、宿主适配器、浏览器/SVG、统一 CLI/MCP 服务。应保留这些结构。当前首要任务是消除语义错误、统一模型入口和补齐宿主生命周期，然后扩展图表。无需改名、重写所有包或把全部 ECharts option 搬入 intent。

审视基线为 `54fbf2a3f7f21a5f5d565e8aed885fe2aac2aa16`。审视前工作区干净；本轮只增加审视、设计、计划与复现资料，不修复产品逻辑、不提交、不发布。该文件是基线快照；后续状态以[行动计划](action-plan-2026-10-31.md)中的证据为准。跨包方案见 [RFC 技术设计](technical-design-2026-10-31.md)。

本次检查源代码、Schema、能力表、适配器、测试、流水线、资源生成和规格；执行全量本地门禁、浏览器回归、定向反例与一个包的离线安装。未调用新的真实模型、未检查远端 CI、未认证所有设备或执行完整安全审计。记忆仅用于定位，下面判断依据本次工作区及实测。

## 当前能力与证据

| 范围 | 实际状态 | 限制 |
| --- | --- | --- |
| 0.1 intent | 柱、线、饼、散点；分组/堆叠等受限能力已实现 | 不应与完整 ECharts 能力等同 |
| 0.1 原生 JSON | guarded partial 与可选 strict-basic 校验 | 默认编译不是完整语义校验；严格模式也仅为小子集 |
| 0.2 intent | 七类：柱、线、饼、散点、柱线组合、漏斗、分类热力图 | 0.2 原生未实现；合法组合主要在编译阶段限制 |

| runtime | 生命周期、ResizeObserver、失败校验保留旧图、版本与去重包装器 | 零尺寸首次挂载不重试；交互状态与稳定行身份未闭环 |

| Agent | Schema/能力发现、校验/编译/SVG、stdio MCP、CLI、RAG 资源 | 工具成功不等于模型任务成功；桌面客户端与远程传输未验证 |
| 新图表 | 雷达、节点连线树、桑基、地图已规划 | 均未实现，不能列入 supported |
| 分发 | 所有包仍为 private alpha | 本次仅 schema 包完成干净安装；全依赖链分发未验收 |

本次验证：

- Node **22.22.3**、pnpm **11.25.0**；与声明的 Node 基线一致。
- `pnpm check`：**147/147 单元/集成测试通过**，生成一致性、文档、格式、lint、类型和演示构建通过；20/20 为公开参考答案自检，不是模型成功率。
- 本机 Chrome **156.0.8078.74**：`pnpm test:browser` **18/18 通过**。Ollama 页面测试使用模拟响应，不能当成真实模型调用。
- 演示主共享资源约 **1.29 MB**，gzip 约 **422 KB**，构建有 >500 KB 提示。这是演示构建证据，不是单独 SDK 的体积指标。
- `@chartnexus/schema` tarball 包含 Schema、类型、公开入口和 LICENSE；在临时干净目录离线安装并通过公开包名导入。其他包、跨平台、完整依赖安装未验收。首次 npm 尝试因用户缓存写入受限失败，改用临时缓存后成功，未修改用户缓存权限。
- [复现脚本](../../specs/0030-project-review/probes.mjs)及[基线观察结果](../../specs/0030-project-review/baseline-observations.json)保留语义问题证据。

## 需要纠正的历史判断

1. 七类图“已实现”仅指明确子集，并不证明零和、所有尺寸、视觉语义、交互和模型成功率均合格。上述反例表明必须分别验收。
2. 前次把窄屏瞬时越界解释为“ECharts 更新动画”没有证据：当前 intent option 明确 `animation:false`。本次只能确认测试等待布局稳定后通过；ResizeObserver/布局调度可能相关，根因尚未复现定位，不以猜测代替结论。
3. `git status` 的 ahead 数量使用本地远端跟踪引用。此前用 SSH URL 直接推送不会自动刷新 HTTPS origin 的跟踪引用；不能据此断言四次提交都没推送。本次没有访问远端核实，不把该计数作为发布证据。
4. 0029 仍为未完成的总范围；固定标签改动不能关闭“完整容器适配”。计划文档、单测数量和整体完成度必须分开。

## 继续保留的设计

保留 core 无 DOM/网络/模型 SDK、JSON 输入不执行代码、可信数据 registry、无效更新不提交、SVG worker 截止/并发预算、独立协议包和中英文资源同步。原生模式继续作为受控扩展入口，不为模型默认开放完整原生 option。远程 MCP、全量框架封装、自动联网取数和高级装饰不是当前基础质量门槛。

后续顺序为：**语义修复和入口统一 → 协议与资源契约 → 布局/可访问性/状态/真实流 → 四类图逐个闭环 → 独立评测与分发验收**。评测基础设施在前期建立，逐阶段复用，而不是最后才开始评测。
